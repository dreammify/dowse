# Dowse

LSP bridge for AI agents. Background daemon manages LSP server connections, file watchers, and diagnostics caching. CLI exposes diagnostics to agents.

## Architecture

- **Daemon** (`internal/daemon/`): Single background process, Unix domain socket at `~/.dowse/dowse.sock`. Manages multiple concurrent LSP sessions keyed by `(workspace_root, lsp_config)`. Sessions are created lazily on first query.
- **Session** (`internal/session/`): One per workspace+LSP combination. Owns the LSP process, file watcher, and diagnostics cache. Detects push vs pull diagnostic model from `ServerCapabilities` during initialization.
- **Transport** (`internal/lsp/transport/`): Wraps `creachadair/jrpc2` and child process management. Handles JSON-RPC over stdio pipes with `Content-Length` framing.
- **Protocol** (`internal/lsp/protocol/`): Generated LSP types. Do not edit `types_generated.go` — run `go generate ./...` to regenerate from the metamodel.
- **Watcher** (`internal/watcher/`): Per-session file watcher using `fsnotify`. Watches directories, filters by extension, respects `.gitignore`, debounces events. Sends `didOpen`/`didChange`/`didClose` to the LSP.
- **Cache** (`internal/cache/`): Per-file diagnostics cache with freshness tracking. Supports blocking waits for fresh diagnostics. Thread-safe.
- **Config** (`internal/config/`): Parses `~/.dowse/config.toml` (global) and `.dowse.toml` (workspace). Maps file extensions to LSP commands.
- **MCP Server** (`internal/mcpserver/`): MCP stdio server exposing Dowse's diagnostics and go-to-definition as tools for AI hosts.
- **TUI** (`internal/tui/`): Terminal dashboard for live monitoring of LSP sessions, built with `tview`/`tcell`.
- **Integration** (`internal/integration/`): End-to-end integration tests against real language servers (gopls, kotlin-lsp, jdtls, typescript-language-server).

## Code Conventions

- All blocking operations accept `context.Context` for cancellation and timeout.
- Use `log/slog` for structured logging.
- All tests run with `-race`. Integration tests use build tag `//go:build integration`.
- Generated code has `// Code generated by ...; DO NOT EDIT.` header and is committed to version control.
- Errors to stderr. Human-readable text to stdout by default; `--json` for structured JSON.
- Use pointers for optional LSP fields (`*DiagnosticSeverity`, not `DiagnosticSeverity`) with `omitempty` JSON tags.
- **Variable naming**: Use descriptive names, not 1-2 letter abbreviations. Spell things out fully (e.g., `managed` not `ms`, `fsEvent` not `ev`, `severity` not `v`, `diagProvider` not `dp`, `extension` not `e`, `gitignorePath` not `gi`). Common 3-letter abbreviations (`ext`, `str`, `res`, `cmd`, `buf`, `req`, `resp`) are acceptable when scope is ~5 lines or fewer. Very standard short names are always acceptable: `ctx`, `err`, `ok`, `mu` (Mutex), `wg` (WaitGroup), `sem` (semaphore), `i`/`j`/`k` (loop indices), single-letter method receivers, and `out` for output channels.

## Key Design Decisions

- **Daemon process model**: Go cannot fork. `dowse start` re-execs `dowse daemon` (hidden subcommand) with `SysProcAttr.Setsid = true` to detach from the terminal.
- **Lazy sessions**: No LSP processes spawn at daemon startup. First `dowse diagnostics <file>` for a workspace+extension triggers session creation (spawn LSP, initialize, start watcher). Cold start blocks until ready.
- **Freshness waiting**: `dowse diagnostics` blocks until diagnostics are fresh (version-based for gopls, timestamp-based fallback for others, inherently fresh for pull-model servers). Default timeout: 5 seconds.
- **Workspace detection**: Walks up from the queried file toward the git root looking for the nearest `.dowse.toml`. That directory becomes the project root. Falls back to the git root if no `.dowse.toml` is found.
- **Push vs pull detection**: Check `diagnosticProvider` in `ServerCapabilities` during init. Present = pull model, absent = push model.

## File Watcher Behavior

- Watches directories (not individual files) via `fsnotify`.
- Filters events by configured file extensions.
- Respects `.gitignore`.
- Debounces per-file (50ms) to coalesce editor save events.
- New directories are automatically added to the watch set.
- Purely reactive — no proactive file scanning at startup.

## Diagnostics Flow

### Push model (e.g., gopls)
1. Watcher detects file change on disk.
2. Session sends `didOpen` or `didChange` to LSP.
3. Cache records the change version/timestamp.
4. LSP sends `publishDiagnostics` notification.
5. Cache updates and signals waiters.
6. `dowse diagnostics` returns fresh results.

### Pull model (e.g., Kotlin LSP)
1. `dowse diagnostics` triggers `textDocument/diagnostic` request.
2. Response is returned directly (inherently fresh).
